PMB REVIT PLUGIN

Vue d’ensemble

PMB Revit Plugin est un add-in Autodesk Revit développé en C#. Son point d’entrée crée l’interface Pimp My BIM dans Revit et charge des modules fonctionnels indépendants. Le dépôt est organisé notamment autour des dossiers Commands, Modules, Models, Data, I18n et Help.

La documentation distingue ce qui est confirmé par le code de ce qui devra être validé sur une build distribuée. Les versions Revit officiellement supportées ne seront annoncées qu’après validation des installateurs.
CAPTURE À AJOUTER · Ribbon Pimp My BIM complet dans Revit

Installation & chargement

Le projet contient un manifeste PimpMyBIM.addin sous forme de template ainsi qu’un projet Visual Studio PimpMyBim.csproj. Revit charge l’assembly via le mécanisme standard des add-ins Autodesk. La distribution publique devra fournir l’assembly compilé, ses dépendances et le manifeste adapté à la version de Revit.

Workflow utilisateur prévu

  1. Télécharger l’installateur correspondant à la version de Revit.
  2. Installer PMB puis démarrer Revit.
  3. Vérifier la présence de l’onglet Pimp My BIM dans le ruban.
  4. Ouvrir un projet puis lancer le module souhaité.

Architecture du plugin

App.cs constitue le point d’entrée de l’application Revit. Les classes du dossier Modules décrivent les fonctions exposées dans l’interface, tandis que les commandes et modèles portent la logique métier et les données nécessaires. Le dossier I18n indique également que l’internationalisation est prévue au niveau du plugin.

Cette section deviendra une documentation développeur séparée si l’API PMB ou des extensions tierces sont ouvertes plus tard.
PMB IFC PLATFORM

Vue d’ensemble

PMB IFC Platform est structurée en deux applications : un backend Python et un frontend web React/Vite. Le backend contient la base de données, le parsing et l’extraction IFC, le moteur de règles et l’export Excel. Le frontend fournit l’interface utilisateur, le viewer, les écrans de projets, règles, analyses et résultats.

CAPTURE À AJOUTER · Dashboard / liste des projets IFC

Workflow de contrôle IFC

  1. Créer ou ouvrir un projet.
  2. Ajouter un fichier IFC.
  3. Explorer le modèle et ses métadonnées dans le viewer.
  4. Sélectionner ou configurer un profil de règles.
  5. Activer les contrôles pertinents pour le projet.
  6. Lancer l’analyse.
  7. Lire les résultats selon leur sévérité.
  8. Exploiter les écarts et conserver l’historique de contrôle.

Le backend dispose également d’un service excel_export.py, ce qui permet de documenter un workflow d’export des données ou résultats vers Excel.

Moteur de règles

Les règles sont configurables et ciblent une classe IFC. Le fichier de configuration actuel montre plusieurs familles de contrôles réellement utilisées par le moteur.

ContrôleUsage
attribute_requiredVérifier qu’un attribut IFC obligatoire est renseigné, par exemple Name ou GlobalId.
pset_requiredVérifier la présence d’un Property Set attendu sur une classe.
pset_property_requiredVérifier la présence d’une propriété précise dans un Pset.
class_detectedDétecter et signaler la présence d’une classe particulière.

Exemples actuellement configurés

Le jeu de règles contient notamment des contrôles sur IfcDoor, IfcSpace, IfcSlab, IfcColumn, IfcBeam, IfcFlowTerminal et IfcBuildingElementProxy. Des exemples vérifient Pset_DoorCommon.FireRating, Pset_SpaceCommon ou encore la présence d’un nom sur les espaces.

Sévérités & interprétation

Les règles peuvent être associées à différents niveaux de sévérité afin de hiérarchiser les écarts.

NiveauInterprétation
CriticalÉcart prioritaire susceptible de rendre la donnée non exploitable pour le contrôle visé.
WarningÉcart à vérifier ou corriger selon les exigences du projet.
InfoPoint de surveillance qui n’est pas nécessairement une erreur.

Exemple : la détection de IfcBuildingElementProxy est configurée en information, car un proxy n’est pas systématiquement incorrect mais peut signaler une perte de spécialisation IFC.

Architecture technique IFC

Le backend regroupe notamment database.py, main.py, rule_sets.py et les services ifc_extractor.py, ifc_metadata.py, ifc_parser.py, rules_engine.py et excel_export.py. Le frontend React/Vite contient l’application principale, les styles, les ressources et la configuration d’internationalisation.

Cette séparation frontend/backend permettra plus tard de produire deux niveaux de documentation : une documentation utilisateur et une documentation d’administration/déploiement.
